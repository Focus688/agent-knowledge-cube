# Z: 测试策略
# 知识域 — 工程类

## 测试金字塔
```
        /
   E2E / ⬆ 慢、贵、少
      /   \
 集成测试   \
/            \
单元测试 ———— ⬇ 快、便宜、多
```

## 覆盖率目标
| 层级 | 目标 | 负责角色 |
|------|------|---------|
| 单元测试 | ≥ 80% | 软件工程师 |
| 集成测试 | ≥ 60% | 软件工程师 |
| E2E 测试 | 核心流程覆盖 | QA 工程师 |
| API 测试 | 100% 端点覆盖 | QA 工程师 |

## 测试命名规范
```
test_<function_name>_<scenario>_<expected>
示例: test_calculate_total_with_discount_returns_correct_amount
```

## 缺陷严重等级
- **P0**: 阻塞上线，系统不可用
- **P1**: 核心功能受损，无替代方案
- **P2**: 功能异常，有替代方案
- **P3**: 体验问题，非功能缺陷
